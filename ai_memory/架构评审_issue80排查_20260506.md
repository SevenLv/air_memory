- **Issue 状态**: 重新打开（"v1.3.1 未解决此问题"）
- **排查时间**: 2026-05-06
- **排查人**: 架构师 Lydia

## 问题描述

用户反映：使用 `start.bat` 启动 AIR_Memory 时，系统仍然会重新下载嵌入模型（all-MiniLM-L6-v2，约 90MB），
尽管 v1.3.1 已经尝试修复（通过将 `HF_HOME` 从条件赋值改为强制赋值）。

v1.3.1 的修复内容：
1. 新增 `init.bat`/`init.sh` 用于预下载模型
2. 在 `start.bat`/`start.sh` 中强制覆盖 `HF_HOME` 指向项目内 `models/` 目录
3. 在 `start.bat`/`start.sh` 启动前检查 `models/hub` 目录是否存在

然而用户报告 v1.3.1 仍未解决此问题。

---

## 根因分析

### 深度代码追踪

#### 1. huggingface_hub 缓存路径解析优先级

通过阅读 `huggingface_hub/constants.py`（v1.13.0），发现缓存路径解析顺序如下：

```python
HF_HOME = os.getenv("HF_HOME", ...)
default_cache_path = os.path.join(HF_HOME, "hub")
HUGGINGFACE_HUB_CACHE = os.getenv("HUGGINGFACE_HUB_CACHE", default_cache_path)
HF_HUB_CACHE = os.path.expandvars(os.getenv("HF_HUB_CACHE", HUGGINGFACE_HUB_CACHE))
```

优先级：`HF_HUB_CACHE` > `HUGGINGFACE_HUB_CACHE` > `HF_HOME/hub`

**v1.3.1 的遗漏**：仅强制覆盖了 `HF_HOME`，但若用户系统或用户级环境变量中已设置 `HF_HUB_CACHE` 或
`HUGGINGFACE_HUB_CACHE` 指向其他路径，`HF_HOME` 的设置将被绕过，导致在错误位置查找模型。

#### 2. sentence_transformers 始终发起网络请求

通过阅读 `huggingface_hub/file_download.py`，发现 `hf_hub_download()` 在 `local_files_only=False`
（默认值）时的行为：

```python
# 即便模型已在本地缓存，默认行为仍会：
# 1. 向 HuggingFace Hub 发起 HEAD 请求，获取最新 commit hash
# 2. 若远端有更新版本 → 重新下载整个模型
# 3. 若网络不可用 → 回退到本地缓存（仅此时不下载）
(url_to_download, etag, commit_hash, ...) = _get_metadata_or_catch_error(
    ...,
    local_files_only=local_files_only,  # False by default
    ...)
```

`HF_HUB_OFFLINE` 控制开关：
```python
HF_HUB_OFFLINE = _is_true(
    os.environ.get("HF_HUB_OFFLINE") or os.environ.get("TRANSFORMERS_OFFLINE")
)
```

**v1.3.1 的遗漏**：未设置 `HF_HUB_OFFLINE=1`，导致 `sentence_transformers` 在每次启动时仍会向
HuggingFace Hub 发起网络请求。若模型在 HuggingFace 上有更新，将触发完整的重新下载（~90MB）。
对于通常在线的用户，这是问题的主要根因。

#### 3. sentence_transformers 模型加载路径

追踪 `SentenceTransformer("all-MiniLM-L6-v2")` 的调用链：

```
SentenceTransformer.__init__()
  → base/model.py: cache_folder = os.getenv("SENTENCE_TRANSFORMERS_HOME")  # None if not set
  → _load_modules() → load_file_path()
  → hf_hub_download(cache_dir=cache_folder)  # cache_dir=None → uses HF_HUB_CACHE
```

当 `SENTENCE_TRANSFORMERS_HOME` 未设置时，`cache_dir=None`，回退到 `HF_HUB_CACHE`（由 `HF_HOME` 派生）。
这部分逻辑是正确的。但问题在于 `HF_HUB_CACHE` 可能被用户环境变量覆盖（问题 1），以及即便路径正确
仍会发起网络请求（问题 2）。

---

## 遗漏的两个根因

| 编号 | 根因 | v1.3.1 是否修复 | 影响 |
|------|------|----------------|------|
| 1 | `HF_HUB_CACHE`/`HUGGINGFACE_HUB_CACHE` 可绕过 `HF_HOME` | ❌ 未修复 | 缓存路径错误 → 模型重新下载 |
| 2 | 缓存命中时仍发起网络检查，若模型有更新则重新下载 | ❌ 未修复 | 在线场景下每次启动都可能触发重新下载 |

---

## 修复方案

### 修改文件：`start.bat` 和 `start.sh`

在环境变量设置部分，新增：

1. **强制覆盖 `HF_HUB_CACHE`**：显式指向项目内 `models/hub/` 目录，防止用户级 `HF_HUB_CACHE`
   覆盖 `HF_HOME` 的设置。

2. **设置 `HF_HUB_OFFLINE=1`**：强制离线模式，禁止 `huggingface_hub` 在启动时发起任何网络请求。
   `init.bat`/`init.sh` 负责预下载模型；`start.bat`/`start.sh` 只使用本地缓存。

3. **设置 `TRANSFORMERS_OFFLINE=1`**：兼容旧版 `transformers` 库，两个变量均由
   `HF_HUB_OFFLINE = _is_true(os.environ.get("HF_HUB_OFFLINE") or os.environ.get("TRANSFORMERS_OFFLINE"))`
   读取，任一设置均生效。

### 修改内容

**start.bat**（在 `HF_HOME` 强制设置之后追加）：
```bat
set "HF_HUB_CACHE=!SCRIPT_DIR!\models\hub"
set "HF_HUB_OFFLINE=1"
set "TRANSFORMERS_OFFLINE=1"
```

**start.sh**（在 `HF_HOME` 强制设置之后追加）：
```bash
export HF_HUB_CACHE="${SCRIPT_DIR}/models/hub"
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

## 修复后效果验证

### 场景 1：正常场景（已运行 init.bat/init.sh）

- `models/hub` 目录存在，模型已预下载 ✓
- `HF_HOME` → `<project>/models` ✓
- `HF_HUB_CACHE` → `<project>/models/hub` ✓（显式设置，不受用户环境变量影响）
- `HF_HUB_OFFLINE=1` → 禁止网络请求 ✓
- `SentenceTransformer("all-MiniLM-L6-v2")` 直接从本地缓存加载，无网络访问 ✓

### 场景 2：用户未运行 init.bat/init.sh

- `models/hub` 目录不存在
- `start.bat`/`start.sh` 检查失败，输出友好错误信息 ✓
- Python 不会被启动，不会尝试下载模型 ✓

### 场景 3：用户系统已设置 HF_HUB_CACHE 指向其他路径

- v1.3.1 中仅 `HF_HOME` 强制设置，`HF_HUB_CACHE` 不受影响 → 模型查找位置错误 ❌
- 修复后：`HF_HUB_CACHE` 也被强制覆盖 → 模型查找位置正确 ✓
- `HF_HUB_OFFLINE=1` 防止任何下载 ✓

### 场景 4：HuggingFace 上的模型有更新版本（在线场景）

- v1.3.1：网络请求发现更新 → 重新下载 90MB ❌
- 修复后：`HF_HUB_OFFLINE=1` 禁止网络请求 → 直接使用本地缓存 ✓

---

## 注意事项

1. **更新 EMBEDDING_MODEL 时**：若用户修改了 `EMBEDDING_MODEL` 环境变量，需重新运行 `init.bat`/`init.sh`
   预下载新模型，再运行 `start.bat`/`start.sh`。`HF_HUB_OFFLINE=1` 不影响 init 脚本（init 脚本
   不设置 `HF_HUB_OFFLINE`，可正常联网下载）。

2. **init.bat/init.sh 不受影响**：init 脚本未设置 `HF_HUB_OFFLINE`，仍可正常联网下载模型。

3. **`models/hub` 检查**：现有的目录检查是必要的（防止 Python 启动时崩溃），但属于弱检查
   （只验证目录存在，不验证具体模型文件）。配合 `HF_HUB_OFFLINE=1`，如果检查通过但模型不完整，
   Python 启动时会有明确的 `EnvironmentError` 错误信息（优于静默下载）。
